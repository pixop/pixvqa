# PU21 metrics for HDR video

PixVQA supports **PU21-PSNR**, **PU21-SSIM**, and **PU21-MS-SSIM** for PQ and HLG video. PU21 converts reconstructed display light (cd/m²) into a perceptually uniform code before scoring. The examples below use `pixvqa` for `./bin/pixvqa` or an executable on `PATH`.

A 10-bit file is not necessarily HDR. Set the transfer to the signal you actually have. `--help-hdr` lists every HDR option, accepted value, and default. This page explains the processing and the recommended settings.

## What PixVQA calculates

For each pixel, PU21 scoring does four operations:

1. Expand stored YCbCr codes to nominal components. Limited range uses the usual 16–235 / 16–240 offsets. Full range uses the full code span.
2. Convert those components to RGB with the selected matrix. The supported pairs are BT.2020 with `bt2020nc` (non-constant luminance) and BT.709 with `bt709`.
3. Turn RGB into display light in cd/m². PQ uses the SMPTE ST 2084 EOTF. HLG uses the BT.2100 inverse OETF and then the reference OOTF below. Chroma is reconstructed first: the default `--hdr-chroma-loc left` is 4:2:0 with horizontally co-sited, vertically centered samples, upsampled with bilinear interpolation.
4. Encode each display value with the PU21 `banding_glare` function from the reference implementation. Values outside 0.005–10,000 cd/m² are clamped to that domain.

PU21-PSNR is PSNR on the encoded RGB, with a peak of 256. That peak is the PU21 encoding of about 100 cd/m². PU21-SSIM and PU21-MS-SSIM are SSIM and MS-SSIM on the encoded luminance. All three differ from `psnr`, `ssim`, and `msssim`, which compare stored sample codes and ignore the transfer.

CPU is the reference implementation. `--metric-device gpu` selects the CUDA implementation for 8-bit and 10-bit pictures when the build includes it.

## PQ (ST 2084 / HDR10)

For limited-range BT.2020 PQ:

```bash
pixvqa \
  --metrics pu21-psnr,pu21-ssim,pu21-msssim \
  --hdr-transfer pq \
  --hdr-primaries bt2020 \
  --hdr-matrix bt2020nc \
  --hdr-range limited \
  -r reference_pq.mp4 -t distorted_pq.mp4
```

PQ maps encoded values to absolute luminance on a 0–10,000 cd/m² scale. Leave `--hdr-peak-nits` unset so PixVQA keeps that scale. Set it only when the evaluation display should clip each component to a lower peak. The 10,000 cd/m² PQ scale is the encoding scale. It is separate from the mastering-display peak, MaxCLL, MaxFALL, and the brightest pixel in the clip. PixVQA does not read those metadata items.

Raw planar YUV needs a resolution and a pixel format:

```bash
pixvqa \
  --metrics pu21-psnr,pu21-ssim,pu21-msssim \
  --hdr-transfer pq \
  --hdr-primaries bt2020 \
  --hdr-matrix bt2020nc \
  --hdr-range limited \
  -r reference10.yuv -s 1920x1080 -f 420p:10 \
  -t distorted10.yuv -s 1920x1080 -f 420p:10
```

## HLG (BT.2100)

For limited-range BT.2020 HLG, name the evaluation display. The defaults are a 1,000 cd/m² peak, a 0 cd/m² black level, and the system gamma derived from that peak:

```bash
pixvqa \
  --metrics pu21-psnr,pu21-ssim,pu21-msssim \
  --hdr-transfer hlg \
  --hdr-primaries bt2020 \
  --hdr-matrix bt2020nc \
  --hdr-range limited \
  --hdr-peak-nits 1000 \
  --hdr-black-nits 0 \
  -r reference_hlg.mp4 -t distorted_hlg.mp4
```

```bash
pixvqa \
  --metrics pu21-psnr,pu21-ssim,pu21-msssim \
  --hdr-transfer hlg \
  --hdr-primaries bt2020 \
  --hdr-matrix bt2020nc \
  --hdr-range limited \
  --hdr-peak-nits 1000 \
  --hdr-black-nits 0 \
  -r reference10.yuv -s 1920x1080 -f 420p:10 \
  -t distorted10.yuv -s 1920x1080 -f 420p:10
```

HLG is a relative signal. Absolute display luminance comes from the evaluation display, not from the brightest pixel, MaxCLL, or the bit depth.

System gamma follows the BT.2100 reference viewing condition. `Lw` is `--hdr-peak-nits` in cd/m²:

```text
gamma = 1.2 + 0.42 * log10(Lw / 1000)
```

Gamma is 1.2 at 1,000 cd/m². Any other peak derives a new gamma unless `--hdr-hlg-gamma` sets one. There is no separate ambient-light control. The accepted override range is `(0, 10]`.

The reference OOTF then maps each scene component `Es` to display light `Fd`. `Ys` is the scene luminance after the inverse OETF, `Lw` is the peak, and `Lb` is `--hdr-black-nits`:

```text
Fd = (Lw - Lb) * Ys^(gamma - 1) * Es + Lb
```

`Lb` is added to each display component. The default is 0 cd/m². A higher black level must be below the peak. When the scene luminance is 0, each display component is `Lb`.

Omitting `--hdr-peak-nits` and `--hdr-black-nits` selects the same 1,000 cd/m², 0 cd/m² model.

## Practical rules

- Resolve every field in this order: per-input option, shared option, stream metadata, then the documented default. `auto` leaves a field unset so a later step can fill it. The reference and the distorted input are resolved separately.
- For a conventional comparison, give both inputs the same transfer and the same evaluation display. A per-input prefix overrides one side, for example `--ref-hdr-transfer pq`.
- Put the real transfer in the stream, or pass `--hdr-transfer pq` or `--hdr-transfer hlg`. `--hdr-transfer auto` does not guess. PU21 requires one of those two transfers.
- Explicit `--hdr-*` arguments take precedence over stream metadata. The examples above are limited-range BT.2020 non-constant luminance. Change the primaries, matrix, and range when the signal differs.
- Contradictory metadata inside one stream is an error. `bt601` is rejected for PQ and HLG.
- Legacy aliases remain accepted: `--tf st2084` is PQ, `--tf stdb67` is HLG, and `--hlg-peak` sets the HLG evaluation peak. The `Input:` line prints those legacy labels. `--tf st2084` is shown there as `st2048`. The resolved parameters are the `HDR:` block.
- PSNR, SSIM, MS-SSIM, and XPSNR still compare stored sample codes when a transfer is set. An explicit `sdr` transfer scores those stored samples as that model.
- An SDR VMAF model rejects PQ and HLG. The bundled HDR VMAF v1.1.8 models automatically label their VMAF input as limited-range 10-bit 4:2:0 PQ with BT.2020 primaries and the `bt2020nc` matrix; users must ensure the video really matches. These model-specific labels do not change PU21's independently resolved HDR settings. HLG stays on the PU21 metrics.
- PU21-SSIM and PU21-MS-SSIM need a picture of at least 11×11 luma samples.
- Accepted numeric ranges are `--hdr-peak-nits` in `(0, 10000]`, `--hdr-black-nits` in `[0, peak)`, and `--hdr-hlg-gamma` in `(0, 10]`.
